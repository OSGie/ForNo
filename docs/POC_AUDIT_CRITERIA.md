# معايير تدقيق خطة PoC

سيُدقّق النموذج عبر خمسة محاور: وضوح قرار المستخدم، سلامة دافع الشراء، سلاسة الجوال وRTL، دقة سلسلة التتبع من الزيارة إلى العقد، واحترام الموافقة والحدود غير الإنتاجية. لا يكفي وجود عنصر تحويل؛ يجب أن يثبت دوره وفائدته وعدم تعارضه مع العناصر الأخرى.

| المحور | سؤال التدقيق |
|---|---|
| تجربة المستخدم | هل يفهم الزائر القيمة والخطوة التالية قبل أن يواجه طلبًا أو نافذة أو نموذجًا؟ |
| التحويل | هل العرض والـCTA وLead Magnet وواتساب يخدمون سياق الصفحة بدل منافسة بعضهم؟ |
| التتبع | هل يحمل كل حدث UID وSession وUTM وموضع العنصر وحالة الموافقة ويمكن ربطه بمرحلة Funnel واحدة؟ |
| الخصوصية | هل تعمل الوسوم الخارجية فقط وفق موافقة قابلة للتغيير، مع بقاء السجل الداخلي الأدنى منفصلًا؟ |
| إثبات المفهوم | هل تعمل الرحلة كاملة دون أسرار إنتاج أو ادعاء ربط خارجي غير موجود؟ |

ولا يعد الحدث Conversion شرائيًا إلا إذا اعتمد الخادم جلسة الدفع التجريبية. ضغط WhatsApp وفتح رابط الدفع وتنزيل الدليل هي تفاعلات اهتمام فقط.

## حدود النطاق

أي توصية تتطلب مدفوعات حية أو إرسال رسائل خارجية أو تخزين إنتاجي أو معالجة PDF خادمية ستسجل كتطوير لاحق، ما لم تغيّر موافقة المستخدم نطاق الـPoC صراحة.

## قاعدة تعارض عناصر التحويل

| عند ظهور هذا العنصر | العنصر الذي لا يظهر في الوقت نفسه |
|---|---|
| نافذة اختيار الشخصية | نافذة Exit-Intent أو Lead Magnet أو أي Dialog آخر. |
| نافذة Exit-Intent | نافذة Lead Magnet وبانر Cookie مفتوح. |
| شريط Cookie | لا يُخفي CTA؛ ويغلق قبل فتح أي Dialog تسويقي. |
| شريط العرض | يظل شريطًا غير Modal ولا يفتح تلقائيًا أي طبقة إضافية. |
