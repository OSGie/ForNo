# تحليل LP1 كمرجع لتصميم موفوتر

> **المصدر:** `/home/ubuntu/upload/LP1.html`، ملف أرسله المستخدم للمراجعة. لا تُنسخ منه نصوص أو أرقام أو شهادات أو وعود تشغيلية حرفيًا.

## ما يُستفاد منه

| النمط | القيمة التحويلية | الترجمة الأصلية في موفوتر |
|---|---|---|
| Hero ثنائي: وعد واضح + واجهة منتج | يربط النتيجة بالمنتج من أول شاشة | لوحة تشغيل مرسومة برمجيًا حسب شخصية العميل، لا لقطة شاشة أو صورة مرجعية |
| ألم محدد ثم انتقال للحل | يجعل العميل يرى نفسه قبل عرض الباقة | قسم ألم مختلف للمكتب عن الشركة، يتبعه «خريطة قرار» لا قائمة مزايا عامة |
| وحدات حسب حالات الاستخدام | يشرح سبب وجود الباقة والإضافة | قسم «حالات التشغيل» تفاعلي: الملفات، الفريق، الإصدار، والنمو |
| خطوات بداية قصيرة | تقلل رهبة الانتقال للشراء | رحلة: اختيار الشخصية، مقارنة السعة، الإضافات، ثم Checkout |
| جدول مقارنة | يحول الفائدة إلى قرار ملموس | مقارنة بين وضوح قرار موفوتر وغموض اختيار باقة/إضافة دون مزاعم عن منصات أخرى |
| عرض باقات مدعوم بتفسير | يشرح فرق السعر بدل مجرد عرض رقم | الباقات الحالية، مع سعة وفريق ونتيجة استخدام وإضافات مرتبطة بالسياق |
| اعتراضات وطمأنة | يزيل الأسئلة قبل CTA الأخير | FAQ عن الشخصية، الباقة الخاصة، الإضافات، والإجمالي قبل الدفع التجريبي |

## ضوابط نقل المحتوى

لا تُنقل من LP1 أرقام العملاء أو الفواتير، أسعار قديمة، ضمانات، وعود زمنية، شهادات، أو ادعاءات توافق/أمان ما لم تكن مصدرًا معتمدًا في بيانات موفوتر. ولا تُستخدم صوره أو تصميماته أو placeholders داخل المشروع. الترجمة المطلوبة هي: **هيكل عرض، إيقاع بصري، وتسلسل إقناعي أصلي**.

## الترتيب المستهدف

1. اختيار الشخصية ثم Hero مخصص.
2. رحلة قرار من ثلاث خطوات.
3. ألم تشغيلي محدد حسب الشخصية.
4. حالات تشغيل تفاعلية توضح ملف/فريق/إصدار/إضافة.
5. مقارنة قرار واضحة.
6. باقات وإضافات وCheckout.
7. أسئلة شائعة وCTA ختامي.
