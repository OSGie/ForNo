# خطة تنفيذ منصة موفوتر

## 1. الهدف والنطاق

سننفذ منصة عربية بالكامل، باتجاه كتابة من اليمين إلى اليسار، تدير رحلة العميل من أول زيارة حتى العقد المؤرشف. وتشمل المنصة بوابة اختيار نوع العميل، صفحتي هبوط مخصصتين، طبقة تتبع أولية، Checkout خادمي التسعير، تحويلًا آمنًا إلى صفحة PayTabs مستضافة، نموذج عقد لا يظهر إلا بعد تأكيد الدفع من الخادم، ولوحة تحليلات داخلية محمية.

> **قاعدة تشغيلية حاكمة:** لن تُعتبر أي عملية دفع ناجحة بسبب إشارة من المتصفح أو صفحة العودة؛ اعتماد الدفع وتفعيل الاشتراك وتوليد العقد تأتي فقط بعد تحقق الخادم من نداء PayTabs العكسي.

## 2. قرارات التنفيذ المعتمدة

| المجال | القرار | سبب الاعتماد |
|---|---|---|
| قالب المشروع | تطبيق React + TypeScript وواجهة Tailwind وخادم Express وtRPC وقاعدة بيانات MySQL/TiDB | هذه هي البنية المتاحة للمشروع الحالي، وتدعم المستخدمين، البيانات، المسارات الخادمية، والتخزين. |
| العربية | `lang="ar"` و`dir="rtl"` عبر التطبيق، مع عزل الأرقام والرموز ذات الاتجاه اللاتيني | يمنع قلب أرقام الهاتف والعملات والروابط في تجربة RTL. |
| الهوية | Violet Blue `#4046B5`، Magnolia `#ECECF7`، Rich Black `#07081A`، أبيض؛ Jomhuria للعناوين وDubai للنص العربي وInter للمحتوى اللاتيني | مأخوذة من دليل الهوية البصرية المرفق. |
| المحتوى | جميع النسخ العامة والـFAQ والأسعار التمهيدية والنماذج في ملفات JSON عربية منفصلة | يمنع النسخ الموزعة في المكونات ويجعل التغيير التجاري آمنًا. |
| التسعير | كل المبالغ قرش صحيح (`integer piastres`) وحساب الضريبة على الخادم بنسبة 14% | يمنع أخطاء الكسور أو التلاعب ببيانات المتصفح. |
| الدفع | PayTabs Hosted Payment Page مع `callback` خادمي و`return` للعرض فقط | توثق PayTabs أن `callback` هو نداء خادم-إلى-خادم مستقل عن تصرف العميل، وأن طلب صفحة الدفع يعيد `redirect_url`. [1] [2] |
| التتبع | SDK مستقل متوافق ES5، وخادم يتحقق من قاموس أحداث ثابت ويكتب البيانات أولًا في قاعدة موفوتر | يحافظ على عمل التتبع في المتصفحات الأقدم ويجعل قاعدة البيانات المرجع الفعلي للتقارير. |
| العقود | تخزين المصدر القانوني كما هو، ودمج حقول محصورة حوله، مع اختبار بصمة لمنع أي انحراف نصي | يحقق شرط الاستخدام الحرفي للملف القانوني. |
| العمل الدوري | نداءات دورية قصيرة ومصادق عليها لمعالجة outbox والمصالحة والتنبيهات؛ لا مؤقتات داخل عملية الخادم | المنصة المدارة لا تضمن بقاء المؤقتات داخل العملية، بينما النداءات المجدولة مصممة لهذا السيناريو. |

## 3. بدائل التشغيل للمسارات المؤجلة

| البديل | الاستخدام المناسب | المزايا | القيود |
|---|---|---|---|
| نداءات دورية خادمية قصيرة | إعادة إرسال أحداث القياس، مزامنة CRM، تسوية عمليات PayTabs المتأخرة، وتجميع مؤشرات اللوحة | مناسبة للمهام الحتمية، مصادق عليها، وقابلة لإعادة المحاولة دون عملية تعمل دائمًا | تحتاج نشر الموقع قبل تفعيل الجدولة، ويجب أن تكون المعالجات idempotent. |
| عملية دائمة تعمل على مدار الساعة | أولوية فقط إن تطلبت الشركة زمن استجابة دون الدقيقة أو معالجة طويلة متواصلة | استجابة متواصلة دون وقت إيقاظ | لها تكلفة استضافة مستمرة وليست ضرورية لمسار callback الحالي. |

سنبدأ بالبديل الأول لأنه يطابق احتياجات الدفع والتحليلات المذكورة. ولن نفعّل أي مهمة دورية قبل إتمام نشر نسخة تعمل وتأكيد المالك لذلك.

## 4. التنفيذ المرحلي

| المرحلة | ما سيُبنى | معايير الانتقال |
|---|---|---|
| 0. حصر الأصول والحواجز | جرد المرفقات، رموز الهوية، سجل الادعاءات، سجل الأسئلة التجارية، وقائمة العبارات المحظورة والمسموحة | توثيق كل قيمة غير مؤكدة كـ`TODO_BUSINESS_INPUT` بدل اختراعها. |
| 1. أساس المشروع | الغلاف RTL، خطوط وألوان موفوتر، نظام المحتوى، فاحص العبارات، فاحص الادعاءات، أدوات المال والوقت، واختبارات أولية | يمر البناء والفحوص وتظهر واجهة عربية متجاوبة من دون أخطاء اتجاه. |
| 2. البيانات والتسعير | جداول الهوية، الجلسات، الأحداث، الكتالوج، الجهات، الطلبات، الدفع، الاشتراكات، العقود، outbox، والتجميعات اليومية؛ مع `quote()` مختبر | جداول البيانات مفهرسة والتسعير يطابق الاختبارات في جميع الحالات الضريبية. |
| 3. القياس والخصوصية | SDK ES5، بصمة الزائر والجلسة، UTM وClick IDs، موافقات الكوكيز، وقاموس 52 حدثًا مع المنع الخادمي لأحداث الدفع | اختبار عبر زيارات متعددة يثبت بقاء first-touch وتحديث last-touch ومنع الأحداث الخادمية المزيفة. |
| 4. الاستحواذ وصفحات الهبوط | بوابة الشخصيات، التوجيه بالـUTM، صفحتا الهبوط، HeroProof، الآلة الحاسبة، النماذج، شريط الجوال، FAQ والنوافذ السياقية | تراجع بصري وجوال وRTL، وظهور الأحداث المطلوبة في طبقة البيانات وسجل الأحداث. |
| 5. Checkout وPayTabs | جهة اتصال، مسودة واستئناف، اختيار خطة وإضافات، اقتباس خادمي، أمر ثابت، إنشاء طلب PayTabs، callback idempotent، وحالات المعالجة/الفشل | اختبار طرفي من اختيار الخطة إلى طلب مدفوع بعد callback موقّع؛ لا يحدث تفعيل من صفحة العودة. |
| 6. العقود والتخزين | نموذج ما بعد الدفع، ترقيم `MOF-CON-YYYY-NNNNNN`، نسختا العقد، اختبار تطابق النص، تخزين الكائنات، وروابط تنزيل موقعة | النص القانوني يطابق المصدر، والملفات لا تكون عامة، ولا يظهر العقد لطلب غير مدفوع. |
| 7. لوحة التحكم والتشغيل | عرض المسار والتحويل وUTM والأداء والزيارات والإيراد وصحة التتبع؛ مع التصفية والتصدير والأدوار | لا يستطيع غير المدير الوصول، وكل مؤشر قابل للتعريف ويأتي من قاعدة موفوتر. |
| 8. الجودة والإطلاق | اختبارات وحدات وخادم وتدفقات، تدقيق الكلمات، تدقيق إمكانية الوصول وRTL والجوال، مراجعة الأمن والأداء، ثم نسخة قابلة للنشر | جميع الفحوص الإلزامية ناجحة، والحقول السرية المطلوبة مسجلة بوضوح. |

## 5. طريقة تقسيم الواجهة

| السطح | المكونات المقترحة |
|---|---|
| الصفحات العامة | `PersonaGateModal`، `ConsentBanner`، `HeroProof`، أقسام المشاكل والمزايا والمقارنة والأسعار والأسئلة، حاسبة الراتب، النماذج والشريط الثابت للجوال. |
| Checkout | اختيار الخطة، محدد الفترة، الإضافات، نموذج بيانات العميل، ملخص الطلب، حقل الكوبون، الموافقات، وزر الدفع. |
| العقد | نموذج بيانات قانونية، معاينة حالة، تنزيل النسخة الكاملة وورقة البيانات. |
| لوحة التحكم | غلاف لوحة التحكم الجاهز في القالب بعد مراجعته، بطاقات KPI، مخطط Funnel، الجداول، مرشحات موحدة، وسجل زائر 360. |

## 6. ضوابط امتثال غير قابلة للتجاوز

| الضابط | التطبيق العملي |
|---|---|
| عبارة المصلحة | السماح بالعبارة: **متوافق مع متطلبات مصلحة الضرائب المصرية** فقط. |
| عبارات ممنوعة | منع صيغ الاعتماد أو الترخيص أو التوثيق المنسوبة إلى المصلحة، في المحتوى والقوالب وJSX. |
| بيانات البوابة | لا يوجد حقل أو منطق يطلب بيانات دخول بوابة الضرائب أو توكيلًا أو تفويضًا. |
| الضمان | إعلان «ضمان استرداد كامل خلال 14 يوم» مع رابط السياسة فقط، من دون وعد بقناة بشرية أو زمن استجابة. |
| الادعاءات العامة | كل رقم/نسبة/عدد عملاء أو وثائق موجود فقط في `claims.json` ويحمل `isPlaceholder`. |
| النص القانوني | لا يعاد تحرير نص `FullContract.html`؛ يسمح فقط بدمج القيم والتنسيق المحيط. |

## 7. مداخلات مطلوبة قبل تفعيل التكاملات الحية

| المدخل | وقت الحاجة | الاستخدام |
|---|---|---|
| بيانات PayTabs (Profile ID، Server Key، والمنطقة/بيئة الاختبار أو الإنتاج) | قبل اختبار الدفع الحقيقي | طلب رابط دفع وتحقق callback وتوقيع النتيجة. |
| كتالوج الباقات النهائي والأسعار وحالة خضوع كل بند للضريبة | قبل إطلاق Checkout تجاريًا | استبدال قيم `TODO_BUSINESS_INPUT` في بيانات الكتالوج. |
| روابط فيديو/GIF/لقطات شاشة للـHeroProof | قبل إطلاق التسويق | تفعيل سلسلة الإثبات البصري الفعلية بدل placeholder آمن. |
| وجهة CRM أو Google Sheet وبيانات الربط | قبل تفعيل مزامنة العملاء المحتملين | تشغيل مزامنة العملاء مع موافقة صريحة فقط. |
| مزود البريد واسم/نطاق الإرسال | قبل إرسال الإيصالات والعقود | تشغيل الرسائل المعاملاتية بعد الدفع. |
| حساب تخزين أو إعدادات النسخة الاحتياطية في Google Drive، إذا طُلبت | قبل تفعيل النسخ الاحتياطي الاختياري | حفظ نسخة إضافية للعقد؛ التخزين الأساسي يبقى كائنات S3. |

## 8. خطة الاختبارات الإلزامية

| نوع الاختبار | الأمثلة |
|---|---|
| وحدات | حساب القرش والضريبة، التحقق من الهاتف المصري، التسعير والعروض، ترتيب العقود، العبارات المحظورة، وبصمة العقد. |
| تكامل خادمي | حفظ الجلسات والأحداث، منع أحداث الدفع من العميل، اقتباس/طلب، callback مكرر أو موقّع خطأ، وروابط التنزيل المصرح بها. |
| تدفق المستخدم | بوابة شخصية → صفحة هبوط → اختيار خطة → Checkout → حالة دفع؛ واختبارات النجاح بعد callback في بيئة PayTabs التجريبية. |
| واجهة | سطح المكتب والجوال، التنقل بلوحة المفاتيح، قراءة الشاشة، الحقول المختلطة الاتجاه، واستجابة رسائل الخطأ بالعربية. |
| أداء | ميزانية JS، حجم الخطوط والصور، وعدم تعطيل العرض بواسطة SDK التتبع أو أصول hero. |

## 9. النتيجة المتوقعة من أول تسليم

سيكون التسليم الأول نسخة قابلة للمراجعة تضم التصميم العربي المتكامل، طبقات البيانات والتتبع والتسعير، ومسار الدفع والعقد تحت مفاتيح تفعيل آمنة. لا تُفعل أي مدفوعات أو مزامنة CRM أو إرسال بريد حقيقي قبل إدخال مفاتيح الحسابات المناسبة واختبارها في بيئة اختبار.
